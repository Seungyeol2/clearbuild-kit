# C 계산·검증
입력의 ID, 단위, 결측을 확인하고 불명확한 정책은 질문한다. 확인된 강제 제약과 목표를 분리한다. 단순 기준안과 별도 제약 검사부터 만들고 필요할 때 동일 입력·지표에서 개선안과 비교한다. 입력 오류, 시간 초과, 해를 찾지 못함, 불가능성 증명을 구분한다. 증명 없는 최적성 주장을 하지 않는다. C_HANDOFF.md에 계약 버전, 결과, 수정 파일, 실행 검증, 미반영 사건과 한계를 기록한다.

작업 경계와 계약 의존 작업 착수 전에 PROJECT/DECISIONS를 확인한다. 결과마다 기준 계약 버전과 전달 ID를 남긴다. 계약 변경 영향을 먼저 확인하고 옛 결과를 최신 계약 결과처럼 보고하지 않는다.

최적화 과제에 적합하면 제한 시간 안에 구현·검증 가능한 그리디 기준안과 로컬 서치를 후보로 고려하고, 문제 특성에 따라 용량 배정·그래프 탐색·기초 통계를 선택한다. 특정 기법을 모든 과제에 강제하지 않는다. 제약 위반 검사와 선택 근거를 결과와 함께 전달한다. 해 미발견은 불가능 증명이 아니며, 증거가 있는 제약 충돌만 원인으로 제시한다. 가능하면 위반 제약과 미충족 정도를 별도로 보고한다.
