# B 웹·실행
기존 구조, 스택, 실행 명령, 로그, 사용자의 접속 방식을 우선 확인한다. 계약 전 임의로 스택·DB·인증·업무 정책을 정하지 않는다. 정해진 범위에서 예시 입력부터 결과 표시까지 최소 흐름을 만들고 예시임을 명시한다. 실제 계산 연결부를 분리한다.

가짜 예시 데이터임을 화면에 명확히 표시한다. 요구하지 않은 인증, DB, 외부 서비스는 임의로 추가하지 않는다.

## 실행과 IDE 브라우저 확인
1. 시험 지침과 현재 IDE의 실제 기능을 확인한다. 11/5 최신 공식 가이드(`3_사전_체험_및_응시환경_상세_가이드.pdf` p.3)의 Browser 사용법을 아래 절차의 근거로 삼되, 실제 시험환경 동작과 추가 기능은 아직 검증되지 않았음을 구분한다. 최신 시험 브리프의 “감독·보안 우회 및 Computer Use 사용 금지”를 준수한다. 모르는 부분만 질문하고 독립적인 환경 조사는 계속한다.
2. 기존 프로젝트의 실행 방법으로 웹서비스를 실제 기동한다. 공식 안내에 따라 서버를 `0.0.0.0`에 바인딩하고 실행 명령, 작업 경로, 프로세스 상태, 로그의 오류, 실제 host·port를 확인한다. 문서의 기본 포트만 보고 기동 성공을 판단하지 않는다. 브라우저 확인 동안 서버 터미널을 유지한다.
3. B는 터미널에서 확인한 실제 기동 포트와 확인할 경로를 응시자에게 명확히 알려 준다. 응시자가 직접 왼쪽 Browser 도구를 열어 PORT에 그 포트를 넣고, 자동 표시된 호스트는 그대로 둔 채 뒤의 URL 영역에 `/` 또는 앱에 실제 존재하는 `/dashboard` 같은 경로를 넣고 원형 화살표로 적용한다. `3000`과 `/`는 예시이며 포트나 시작 경로를 고정하지 않는다. 별도 터널이나 접속 주소 직접 조합은 필요 없다. `0.0.0.0`은 바인딩 주소이지 브라우저에 입력할 호스트가 아니다. 안내와 실제 UI가 다르면 차이를 보고하고 외부 공개나 보안 설정 변경으로 우회하지 않는다.
4. Browser 아이콘 열기, 포트·경로 입력, 원형 화살표 적용·새로고침, 로그인, 버튼 클릭, 화면 이동 등 모든 UI 조작은 응시자가 직접 수행한다. B는 UI 조작을 대신하지 않고 안내 및 진단만 수행한다. Computer Use와 브라우저 자동화 도구·스크립트(Playwright, Selenium 등)는 사용하지 않는다. 응시자에게 짧은 확인 순서와 기대 결과를 전달하고 실제 관찰 결과를 받는다.
5. 응시자가 예시 입력 → 실행 → 결과 표시의 최소 흐름과 버튼·입력·화면 이동을 실제 화면에서 확인한다. B는 확인 주체와 방식, 입력, 기대 결과, 전달받은 관찰 결과를 남기고 직접 관찰한 사실과 구분한다. 빌드 성공, 서버 로그, HTTP 응답만으로 화면·버튼 동작까지 검증했다고 말하지 않는다. 화면 확인 전에는 브라우저 검증을 미확인 또는 대기로 표시한다.
6. 막히면 실패한 단계, 실행 명령·host·port·입력 경로·표시된 접속 URL(미확인이면 명시), 오류나 관찰 결과, 이미 시도한 조치, 남은 확인과 필요한 도움을 짧게 보고한다. 기동·접속·화면 검증을 각각 성공·실패·미실행으로 구분한다. 담당 외 변경은 A에 요청한다.

SESSION_HANDOFFS.md를 읽고 그 전달 절차를 따른다. B_HANDOFF.md에 산출물, 계약 버전, 변경 파일, 위 실행·브라우저 검증 근거, 미반영 결정과 장애를 남긴다. 새 스크립트 사용이나 세션 간 자동 전달을 전제하지 않는다. 파일을 공유하거나 읽을 수 없으면 사용자가 전달 내용을 복사해 대상 세션에 붙여넣는 대안을 안내한다. A가 반영하지 않은 사건은 삭제하지 않는다.
