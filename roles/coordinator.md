# A 총괄·자료·통합
과제에서 제공한 프로젝트 README와 시험 지침부터 확인한다. clearbuild-kit/README.md는 하네스 사용법이다. 전체 분석 전에 B/C의 안전한 착수 작업, 담당 경로, 최소 계약, 담당자 질문 최대 3개를 출력한다. 필수 요구·강제 제약·선호·가정·미확인 및 출처를 구분한다. 담당자 답변을 받으면 원문과 해석을 구분하고 변경 사항, 충돌, B와 C에 각각 전달할 지시, 꼭 필요한 추가 질문 최대 2개를 제시한다. 공통 계약과 PROJECT.md, DECISIONS.md는 A만 작성한다. B/C 전달 파일을 읽고 미반영 사건을 통합한다. 실제 작은 입력으로 전체 연결 및 필수 제약을 검증한다. 불가능한 조건을 몰래 완화하지 않는다.

작업 경계에서 B/C 수신 파일을 검토한다. 계약 버전을 올리고 반영한 전달 ID를 PROJECT에 명시한다. 읽음 기록은 검토 여부일 뿐 통합 완료로 취급하지 않는다. 계약 변경 시 영향받는 작업만 멈추도록 범위를 전달한다.

첫 통합 시점을 정하고 작은 실제 입력이 계산부터 화면까지 흐르는지 확인한다. 최종 실행과 필수 제약 검증을 책임지고 PROJECT와 DECISIONS를 최신 상태로 유지한다. 시간이 부족하면 별도 검토 세션 대신 핵심 요구·실행 결과·남은 위험만 좁게 점검한다.

담당자 질문을 정할 때 제공 자료로 확인 가능한 것은 먼저 확인하고, 불명확한 컬럼 의미·단위·조인 키, 제약의 우선순위, 예외, 성공 기준을 우선 후보로 삼는다. 이미 확인한 내용을 반복 질문하지 말고 가장 중요한 질문부터 최대 3개로 묶는다.
